EnterraEdit

One script tag, no build step, no framework. Everything below is a plain <textarea> that gets upgraded in place, the form still submits normal HTML.

1. Plain auto-init (browser language)
2. German (lang="de" on the wrapper)
3. Arabic: automatic RTL (lang="ar")
4. Forced RTL on English (data-dir="rtl")
5. No toolbar, spellcheck off
6. Themes, switch them live

Presets, plus a custom accent. The accent derives readable link and active-state colours automatically for the mode in use.

accents:

theme: light

7. Branding, badge on or off

Invisible attribution (a data-ee-source attribute and a head comment) is always present. The visible badge is opt-in via data-badge="true", and one flag turns both off.

8. Sizing: width, height, rows, growth
9. Fonts: opt in, or inherit from the page

No webfonts are downloaded. The default is inherit, so the editor matches whatever font the surrounding site uses. Presets are all system fonts, and RTL languages get a script-appropriate stack automatically.

10. Real-world patterns: pick the one that matches your form

A. Normal HTML POST. Nothing special needed, the textarea stays in the form and is synced as you type. Your existing server code is unchanged.

<form method="post" action="/contact">
 <input name="email">
 <textarea name="message" data-enterraedit></textarea>
 <button>Send</button>
</form>

B. AJAX / fetch. Read the field whenever you like, it is always current, no submit required.

fetch('/api/ticket', {
 method: 'POST',
 body: new FormData(form)
});

C. JavaScript frameworks. Setting ta.value updates the editor, and typing updates ta.value, so v-model / onChange wiring works both ways.

D. Ticket / support systems. Post the HTML straight in, or convert to text if the destination is plain:

const html = ta.value; // <p>Hello <strong>there</strong></p>
const text = ed.getText(); // "Hello there" (plain)
(click to inspect)
11. Modes: comment, standard, full

A contact form does not need headings and code blocks. data-mode selects a toolbar without naming every button.

12. Images and tables

Insert an image by URL, or pick a file to embed as a data URI. Embedding suits a small screenshot and is a bad idea for a photograph: a 500 KB image becomes about 667 KB inside the form field. The dialog warns above 200 KB.

13. Button picker: build your own toolbar

Every button the editor has. Tick what you need and copy the resulting attribute. Nothing is implied about what the field accepts, only which controls are shown.

14. Paste and drop images

Copy a screenshot and paste it here, or drag an image file in. Both are embedded as a data URI, validated the same way as any other source, and warned about if they are large. SVG files are refused, because SVG can carry script.
